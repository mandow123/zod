# KAI 卡时优先的手机版信息架构

状态：产品布局规格，依据《KAI Cloud 统一卡时交易与全品类算力资源闭环白皮书 V1.0》整理。  
主执行基线已升级为 `KAI_CLOUD_MASTER_EXECUTION_PLAN.md`；如本文与主方案冲突，以主方案为准。  
约束：保留五栏；“消息”继续位于“我的”左侧；不把网站缩小后搬进 App。

## 1. 产品中心

KAI Cloud App 的核心不是人民币收银台，也不是某一种 GPU，而是一个可以跨 GPU、模型、Token、云主机、存储与容量使用的 `KAI 卡时账户`。

必须始终成立：

- 人民币只用于购买 KAI 卡时；算力订单只使用 KAI 卡时支付。
- `1 KAI 卡时 = ¥1.002` 是固定购买价；账本精度为 `0.000001 KAI 卡时`。
- KAI 卡时是站内服务结算额度，不展示收益率、涨跌、提现行情、自由转账或交易市场。
- 商品保留原生单位，例如 GPU 物理卡时、百万 Token、实例时、TiB 存储时、机柜月；不能都简称为“卡时”。
- 商品和结账同时显示人民币参考价与应付 KAI 卡时，但主支付数字是 KAI 卡时。
- 余额不足时优先提供“按精确差额充值并支付”，不要求用户先离开订单猜要充多少。

## 2. 双视角导航

同一账号采用两个可一键切换的工作视角，完整规格见 `KAI_DUAL_MODE_MOBILE_IA.md`：

- 使用算力：`首页 / 市场 / 订单 / 消息 / 我的`
- 提供算力：`工作台 / 资源 / 上架 / 消息 / 我的`

顶部固定使用 `使用算力 / 提供算力` 分段开关。它只切换界面上下文，不切账号、不创建第二份余额，也不改变服务端权限。

### 首页：我的算力状态

首屏从“市场宣传海报”转为可行动的账户首页：

1. 顶部身份与通知。
2. 卡时资产卡：
   - 可用 KAI 卡时；
   - 冻结卡时；
   - 约合人民币参考值；
   - `充值卡时` 主按钮；
   - `账单明细` 次按钮。
3. 进行中的任务：待支付、开通中、待验收、使用中，优先展示需要用户操作的订单。
4. 快速购买：GPU、模型与 Token、云主机、存储、预留容量。
5. 最近账本：充值、订单扣减、退款、租金收入，每项明确业务依据。

首页只在未登录时展示简洁价值说明；登录后不继续占用首屏展示大面积营销 Banner。

### 市场：先看原生资源，再看卡时成本

市场以任务和资源分类浏览，商品卡必须同时回答：

- 买到什么资源，以及原生单位；
- 独享、共享、虚拟化或切片方式；
- 地区、可售时间和交付方式；
- 人民币参考价；
- 应付 KAI 卡时；
- 余额是否足够；
- 验收与退款边界。

列表主价格示例：

`31.137725 KAI 卡时 / GPU 物理卡时`  
`参考 ¥31.20 · 独享 H100 80GB`

市场顶部不放“充值”。用户在购买意图明确后，结账页再提供精确差额充值，避免把 App 做成储值工具。

市场内增加买方任务入口：

- `发布算力需求`：找不到现成资源时发布需求；
- 供应资源通过顶部切换到“提供算力”视角，再由中间的 `上架` 进入完整审核流程。

### KAI 卡时：两个视角共用的账户

KAI 卡时不占用底部导航：使用算力首页显示余额卡，结账页显示应付和精确差额，“我的”提供完整账户入口；提供算力工作台显示成交与待结算摘要。

页面结构：

1. 余额总览：可用、冻结、待入账。
2. 两个主动作：`充值 KAI 卡时`、`查看明细`。
3. 普通充值：5 KAI 卡时整数倍，明确 `5 KAI 卡时 = ¥5.01`。
4. 订单差额充值：只在从待支付订单进入时出现，金额由服务端精确计算并绑定订单。
5. 账本筛选：全部、充值、购买、退款、收入。
6. 规则说明：固定购买价、不可自由转账、不承诺升值、退款去向。

不提供：转账、收款码、收益、涨跌、提现快捷入口、公开买卖盘。

### 消息：继续位于“我的”左侧

保留当前位置，分类调整为：

- 订单：预留即将过期、已扣卡时、待验收、到期清理；
- 卡时：充值到账、扣减、退款、冲正、余额不足；
- 交付：资源准备、连接检查、故障与恢复；
- 系统：账户安全、协议和服务状态。

高风险消息必须带业务对象和可验证状态，不使用“支付成功”泛化替代“人民币充值已验签入账”或“订单卡时已扣减”。

### 我的：主体、订单与供应方角色

结构建议：

- 个人/组织身份；
- 我的订单；
- 我的需求；
- 发票与合同；
- 供应商中心（资源、挂牌、交付、租金）；
- 账户与设备；
- 协议、隐私、卡时规则与账户删除。

卡时余额不重复作为主模块，只保留进入卡时中心的摘要行。

## 3. 关键页面

### 商品详情

从上到下：真实库存状态 → 原生资源与配置 → 数量/时段 → KAI 卡时总价 → 人民币参考价 → 交付 → 验收 → SLA/退款 → 创建价格快照。

H100 首单示例必须准确显示：

- NVIDIA H100 80GB 独享物理 GPU；
- 1 张 × 1 小时；
- 人民币参考价 ¥31.20；
- 固定购买价 1 KAI 卡时 = ¥1.002；
- 应付 31.137725 KAI 卡时；
- 账本扣减 31,137,725 micros 只用于账单详情，不作为普通用户主视觉。

### 结账

结账不是人民币直接购买资源，分三种状态：

1. 余额充足：
   - 显示余额、订单应付与支付后余额；
   - 主按钮 `支付 31.137725 KAI 卡时`。
2. 余额不足：
   - 显示当前余额与精确差额；
   - 主按钮 `充值差额并支付`；
   - 支付渠道只对应这笔人民币充值。
3. 支付结果待确认：
   - 显示 `充值确认中，请勿重复支付`；
   - 只有服务端异步通知验签、TOPUP 入账、ORDER_CAPTURE 成功后，订单才显示已支付。

结账页固定展示库存预留倒计时，默认 15 分钟；到期后必须重新获取价格和库存。

### 订单工作台

以单条履约时间线组织：

`待支付 → 已支付 → 开通中 → 待验收 → 使用中 → 已完成 → 已清理`

异常状态并行展示 `退款中 / 已退款 / 争议`。每一步显示时间、责任方、证据摘要和下一动作。退款必须区分：

- 退回 KAI 卡时账户；
- 订单专用充值在满足条件时人民币原路退款。

## 4. 首次用户路径

最短路径应是：

`浏览 H100 → 选择 1 张 × 1 小时 → 创建价格快照与库存预留 → 登录/建立交易主体 → 充值 31.137725 KAI 卡时对应人民币 → 异步确认 → 原子扣减卡时 → 查看交付 → 验收 → 使用 → 清理 → 账单可追溯`

用户不需要先理解 micros、账本分录或供应方结算。复杂性留在服务端；界面只清楚回答“我有多少、这单要多少、为什么扣、失败退到哪里”。

## 5. 上架与文案边界

- 应用分类建议仍为企业/生产力工具，不描述为钱包、交易所、投资或理财应用。
- 商店描述必须写明“人民币购买站内 KAI 卡时，再用卡时购买可验收的算力服务”。
- 不使用“充值即升值”“一卡通兑资产”“自由流通”等表达。
- 充值、卡时扣款、退款、供给方结算上线前必须经过法务、财务、支付渠道和 Google Play Billing 适用性复核。
- 上架截图只能来自连接正式后端、具有真实可用数据或审核演示数据的构建；当前“连接中断”截图不得提交。

## 6. 需要先于前端实施的后端不变量

1. 组织级 KAI 卡时账户与百万分之一精度余额。
2. 不可修改、平衡双分录账本，错误只能冲正。
3. 版本化汇率与订单价格快照。
4. TOPUP 只由已验签的人民币支付回调发行卡时。
5. ORDER_CAPTURE 只扣 KAI 卡时，不直接调用人民币支付。
6. 订单差额充值与订单扣款原子化、幂等化。
7. ORDER_REFUND、原路人民币退款和卡时销毁/冻结一致。
8. 余额不得为负，同一业务键不能重复入账或扣款。
9. 日终核对支付金额、发行卡时、余额、订单扣减和清算账户。
10. 上述能力未通过真实首单和退款演练前，前端不得显示为可用。
