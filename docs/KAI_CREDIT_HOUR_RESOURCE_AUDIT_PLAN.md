# KAI Cloud 卡时闭环与资源上架审核方案 V1.0

状态：方案已定稿，尚未实施。后续开发以本文为主线，按小阶段推进。  
主执行基线已升级为 `KAI_CLOUD_MASTER_EXECUTION_PLAN.md`；如本文与主方案冲突，以主方案为准。  
依据：《KAI Cloud 统一卡时交易与全品类算力资源闭环白皮书 V1.0》。  
产品约束：人民币只能购买 KAI 卡时；所有算力订单只能使用 KAI 卡时支付；`1 KAI 卡时 = ¥1.002`。

## 1. 这次方案解决什么

正式上架前必须建立三条不能绕过的链路：

1. **资金链**：人民币支付 → 充值到账 → KAI 卡时双分录账本。
2. **资源链**：供应商提交 → 资源验真 → 定价审核 → 获准发布。
3. **订单链**：库存与价格快照 → 卡时扣款 → 交付验收 → 退款/结算/清理。

页面只是上述状态的呈现，不得让客户端自行计算余额、认定支付成功、修改审核价格或跳过审核发布。

## 2. 产品布局定案

同一个账号采用两个工作视角，顶部一键切换，不要求注册买方和供应方两个账号：

- 使用算力：`首页 / 市场 / 订单 / 消息 / 我的`
- 提供算力：`工作台 / 资源 / 上架 / 消息 / 我的`

用户界面称为“使用算力/提供算力”，不显示生硬的买方/卖方。提供算力视角的中间 `上架` 为抬高主按钮；使用算力视角不显示含糊的“发布”，找不到资源时从市场发布算力需求。消息在两边都位于“我的”左侧。

登录状态、组织关系、卡时账户和安全设置共用；切换只改变工作上下文，不能绕过供应商资质、资源验真或价格审核。完整交互规格见 `KAI_DUAL_MODE_MOBILE_IA.md`。

### 首页

- 首屏显示可用卡时、冻结卡时、待入账以及充值和账单入口；
- 优先显示待支付、开通中、待验收、使用中的订单；
- 提供 GPU、模型/Token、云主机、存储和预留容量快捷入口；
- 登录后不再以网站式大 Banner 占据首屏。

### 市场

每张资源卡先说明买到什么，再说明支付多少：

`31.137725 KAI 卡时 / GPU 物理卡时`  
`参考 ¥31.20 · 独享 H100 80GB · 已验真/价格已审核`

点击审核标识可查看脱敏的资源审核摘要、价格依据、审核时间和有效期。

### KAI 卡时账户

- 可用、冻结、待入账余额；
- 普通充值和订单精确差额充值；
- 充值、购买、退款、收入、冲正账本；
- 固定购买价、不可自由转账、无收益承诺等规则；
- 不提供 K 线、公开买卖盘、收益、收款码或自由提现入口。

它不占底部栏目：使用算力首页、结账页和两边“我的”均可进入；提供算力工作台显示成交和待结算摘要。

### 消息

按订单、卡时、交付、系统分类。消息必须说清业务事实，例如“充值回调已验签并入账”或“订单已扣减卡时”，不笼统写成“支付成功”。

### 我的

组织/个人身份、订单、需求、合同发票、供应商中心、设备安全、协议与账户删除。供应商中心承载资源提交、补充材料、审核进度、挂牌、交付和租金结算。

## 3. 资源上架采用“双审核”

一个挂牌必须同时通过两个相互独立的审核：

### A. 资源真实性与可交付审核

验证“资源真的存在、属于或合法授权给供应商、配置准确、在承诺时段可交付”。至少提交：

- 供应商主体、所有权或转授权证明；
- 资源类型、原生计量单位、地区、可售时间窗；
- GPU/节点/实例的配置与脱敏唯一标识；
- 在线挑战和自动采集证据，例如 GPU 型号、显存、UUID、驱动/CUDA、MIG、NVLink/拓扑、CPU、内存、存储和网络；
- 基准测试、稳定性、故障率与当前占用情况；
- 交付方式、验收项、SLA、退款边界、到期清理与数据隔离方案；
- 电费、网络、存储、IP、服务、税费等包含项和排除项。

自动采集只能帮助验真，最终仍需审核员确认。公开行情、宣传截图或数据库里的产品型号种子不能单独证明真实库存。

### B. 人民币基准价与卡时价格审核

供应商提交的是“建议人民币原生单价”和依据，不得直接填写最终 KAI 卡时价格。价格审核需确认：

- 原生计量单位和配置可比；
- 供应方成本、交付与运维成本；
- 地区、时段、独享/共享、虚拟化/MIG、网络和 SLA 差异；
- 至少两类可追溯对比依据及采集时间；
- 买方最终价包含哪些费用，结账后不得再出现未披露费用；
- 异常低价、异常高价、关联供应商和短时大幅调价风险。

KAI-SCH 或市场指数只作为价格审核的对比证据，不直接决定买方应付卡时，也不能替代真实库存和交付审核。

建议执行四眼原则：资源审核员与价格审核员不得为同一人；高金额或高风险资源增加财务/合规复核。

## 4. “一小时值多少卡时”的统一算法

### 小时型资源

GPU、GPU 节点、CPU 服务器、模型实例、Token 吞吐能力和云配额等小时型资源，审核结果统一展示：

`每原生资源小时应付 KAI 卡时 = 向上取 6 位小数（审核人民币小时价 ÷ 1.002）`

服务端不得使用浮点数。存储单位：

- `1 KAI 卡时 = 1,000,000 卡时 micros`
- `¥1 = 1,000,000 人民币 micros`
- `1 KAI 卡时 = 1,002,000 人民币 micros`

整数计算：

```text
卡时 micros = ceil(
  订单人民币参考总额 micros × 1,000,000
  ÷ 1,002,000
)
```

白皮书首单示例：

```text
独享 H100 80GB × 1 张 × 1 小时
审核人民币参考总额：¥31.20
31.20 ÷ 1.002 = 31.137724550...
向上取 6 位：31.137725 KAI 卡时
账本扣减：31,137,725 卡时 micros
```

### 非小时型资源

不得为了统一视觉强制折算成“一小时”：

- Token 用量：每百万 Token；
- 存储：每 TiB·小时；
- 机柜/电力：每机柜月或每 kW·月；
- 预留容量：按合同定义的容量时；
- 其他资源：保留审计通过的原生单位。

界面始终同时显示“原生资源单位”和“KAI 卡时支付单位”，避免把 KAI 卡时误解为某张 GPU 的物理运行小时。

## 5. 审核状态与发布门禁

建议状态机：

```text
草稿
  → 已提交
  → 资源审核中
  → 价格审核中
  → 已批准
  → 已发布
```

任一环节可进入：`待补材料 / 已驳回 / 已过期 / 需重新定价 / 已暂停 / 已下架`。

发布接口必须在同一事务内验证：

- 供应商主体有效且有发布权限；
- 资源审核版本已通过且未过期；
- 价格审核版本已通过且未过期；
- 真实库存和可售时间有效；
- SLA、验收和退款规则完整；
- 审核价、卡时换算规则和证据摘要已生成不可变版本。

不允许客户端仅凭“审核状态文字”为资源挂牌，也不允许管理员直接绕过状态机改成已发布。

## 6. 审核结果的数据形态

每次批准生成不可修改的版本，至少包含：

- 资源审核版本、资源指纹摘要、证据摘要、审核人和时间；
- 原生资源类型、单位、配置、区域和交付边界；
- 审核通过的人民币原生单价；
- 卡时汇率规则版本 `KAI_CREDIT_RATE_V1`；
- 每原生单位应付卡时 micros；
- 价格包含项、税费口径、SLA、验收和退款规则；
- 生效时间、失效时间、决定与理由；
- 对比价格区间和异常风险标签。

每个订单创建时再次固化“订单价格快照”。挂牌后即使出现新价格，也不能回写已创建订单。

建议默认有效期，可由后台配置：

- 价格审核：30 天；
- 资源与技术审核：90 天；
- 提交审核时的在线挑战证据：24 小时内生成。

以下情况立即触发重审：价格、配置、地区、计量单位、独享方式、SLA 或交付方式变化；关键证据失效；异常故障/退款；供应商资质变化；资源清理失败；审核周期到期。

## 7. 用户端审核信息布局

### 市场卡片

- 主价格：KAI 卡时/原生单位；
- 次价格：人民币参考价；
- `资源已验真` 和 `价格已审核` 两个独立标识；
- 可售时间、独享方式、地区和交付摘要。

### 资源详情

- 真实配置和脱敏资源标识；
- 最近资源审核时间、价格审核时间和有效期；
- 人民币价格依据摘要及卡时换算过程；
- 包含/排除费用；
- 验收清单、SLA、退款和清理规则；
- 审核报告摘要入口。

### 结账

服务端按数量、时长和版本化单价重新计算：

- 人民币参考总额；
- 应付 KAI 卡时；
- 当前、冻结和支付后余额；
- 15 分钟库存/价格预留倒计时；
- 余额不足时的精确差额充值。

客户端显示服务端签发的价格快照，不能自行相乘后提交总价。

## 8. 审核后台布局

后台以“待审核工作台”而不是普通表单为核心：

1. 左侧：待审队列、风险级别、等待时长和补件状态；
2. 中间：资源实测配置、在线证据、库存窗口、基准测试和交付规则；
3. 右侧：建议人民币价、可比证据、费用组成、卡时自动换算和偏离警告；
4. 底部固定操作：通过资源、通过价格、要求补件、驳回、暂停；
5. 所有决定写入审计日志，批准后生成版本，不能覆盖原记录。

## 9. 卡时与订单后端不变量

- 卡时账户归属个人或组织，组织之间严格隔离；
- 使用百万分之一精度、不可修改且平衡的双分录账本；
- 错账只能用冲正分录修复，禁止改历史余额；
- 人民币支付回调验签成功后才能执行 `TOPUP`；浏览器返回页不能入账；
- 算力订单只能执行 `ORDER_CAPTURE` 扣卡时，不直接扣人民币；
- 精确差额充值的 `TOPUP + ORDER_CAPTURE` 必须原子、幂等；
- 余额不能为负，同一业务键不能重复发行或扣减；
- 订单扣款按价格快照在供应商收入与平台服务收入之间平衡分账；
- 退款区分退回卡时和符合条件的人民币原路退款；
- 每日核对人民币收款、卡时发行、账本余额、订单扣款、退款和供应商结算。

## 10. 分段实施顺序

每一段单独验收，避免一次改动过大。

### 第 1 段：冻结规则与数据库设计

交付：卡时账户/账本、审核版本、价格快照、组织隔离和状态机迁移设计。  
验收：演算 H100 示例、并发扣款、幂等和历史版本不可变。

### 第 2 段：卡时双分录账本

交付：账户、可用/冻结余额、TOPUP、冲正、ORDER_CAPTURE、ORDER_REFUND、收入/佣金分录。  
验收：平衡性、零负余额、并发、重放和日终对账测试。

### 第 3 段：人民币充值闭环

交付：普通充值、订单精确差额充值、异步验签、待确认恢复和原路退款约束。  
验收：支付成功/失败/重复回调/超时/退款全路径演练。

### 第 4 段：资源与价格审核中心

交付：供应商提交、自动验真、双审核、证据、版本、有效期、重审和发布门禁。  
验收：未审、单边通过、过期或被暂停的资源均无法发布和下单。

### 第 5 段：卡时订单闭环

交付：库存预留、价格快照、卡时支付、交付、验收、退款、供应商收入和资源清理。  
验收：真实 H100 `1 张 × 1 小时` 首单及一次完整退款演练。

### 第 6 段：按本方案调整手机版

交付：双视角切换、两套语义清晰的五栏导航、共用卡时账户、审核标识、资源详情、结账和订单时间线。  
验收：真机冷启动与全流程；无直付人民币资源、无客户端自算价格、无未审核挂牌入口。

### 第 7 段：上架与生产门禁

交付：正式域名/API、支付渠道、隐私/条款、Data Safety、金融功能声明、商店物料和审核账号。  
验收：生产首单、退款、账户删除、灾备和上架检查全通过。

## 12. 本方案的上线红线

出现任一情况不得开放正式交易：

- 人民币能直接购买算力订单；
- 支付页面返回即可给卡时入账；
- 供应商能自行填写最终卡时价或绕过审核；
- 商品不显示原生单位，或把 KAI 卡时描述成 GPU 物理小时；
- 资源、价格或审核已过期仍可下单；
- 订单没有不可变价格快照；
- 余额能变负、重复回调能重复入账、历史账本可被修改；
- 退款、供应商收入或平台佣金无法与原始订单逐笔核对；
- 正式商品依赖演示库存、静态产品型号或未经验证的公开行情。
