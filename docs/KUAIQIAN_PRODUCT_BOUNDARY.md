# Zod × 快钱产品对接边界

状态：产品经理已裁决
日期：2026-08-17

## 核心原则

快钱负责法币进出，KAI 卡时负责 App 内全部资源交易。

Zod 不采用“每笔资源订单通过快钱支付并在验收后分账”的模式。市场、商品详情、下单、订单、履约、资产和供应商上架只使用 KAI 卡时，不展示人民币参考价或换算关系。

## 第一阶段：用户充值

```text
用户创建卡时充值单
→ Zod 服务端创建快钱收银台
→ 用户在快钱完成付款
→ 快钱回调或 Zod 主动查询确认到账
→ Zod 幂等发放 KAI 卡时
```

App 从收银台返回后只能显示“已返回 Zod，正在确认支付结果”，不得根据回跳参数判断支付成功。回跳只携带不透明的 `topupId`；金额、币种和支付状态以 Zod 服务端为准。

充值页允许展示人民币充值金额、预计到账卡时和固定换算规则。充值状态包括：待支付、支付确认中、卡时发放中、卡时已到账、支付失败、已关闭、异常待核对、退款处理中、退款完成。

## 第二阶段：供应收益兑付

仅在快钱书面确认支持企业付款、商户付款或合规代付后接入：

```text
供应商申请兑付
→ 平台审核并冻结卡时收益
→ 快钱或公司对公渠道付款
→ 最终确认到账
→ 完成兑付
```

快钱不参与资源订单、平台手续费计算或卡时分账。平台手续费在卡时账本结算时扣除。如果快钱不支持合规企业付款，兑付改用公司对公银行付款并记录可核验流水。

## 后端状态与安全边界

快钱支付状态与卡时入账状态必须分开保存。支付成功但账本入账失败时进入 `paid_uncredited`，由恢复任务继续处理，不能要求用户再次付款。

回调与主动查询必须汇合到同一个幂等处理器，并校验签名、证书、商户号、充值单号、快钱流水、金额、币种、状态和重复事件。同一快钱流水不得绑定不同充值单。App 无权修改支付状态。

资源订单取消或履约退款只退 KAI 卡时。只有充值现金退款或支付渠道拒付才进入快钱退款流程；卡时已经消费或无法完整追回时必须进入人工风控。

## 现在可开发

- 支付通道适配器接口与快钱沙箱模拟器。
- 充值单、支付事件收件箱、退款单、兑付付款单和对账差异表。
- 充值、退款、兑付状态机与恢复任务。
- App 充值结果查询页、回跳路由、继续支付和重新查询。
- 重复回调、迟到回调、金额不一致、支付成功但卡时未入账等自动化测试。

## 与现有产品的对接位置

不新增独立“支付”底部入口。用户从“我的 → KAI 卡时 → 充值卡时”进入，选择金额后打开快钱 App/H5 收银台；返回 Zod 后仍停留在这笔充值记录，状态先显示“确认中”。

现有产品接口保持不变：

- `POST /mobile/v1/credits/topups`：创建充值单并取得收银台信息；快钱只作为新增支付通道。
- `GET /mobile/v1/credits/topups/:topupId`：App 返回后查询服务端权威状态。
- `GET /mobile/v1/credits/topups`：展示充值记录和异常核对状态。
- 快钱异步通知：单独新增服务端回调路由，验签成功后进入现有统一入账处理器。
- 恢复任务：主动查询快钱订单，并与异步通知汇合；两条路径不得各自发放卡时。

App 不接触商户私钥、证书、签名字段、快钱流水或服务端回调地址。快钱接入完成后，市场购买按钮、资源订单、算力交付、卡时结算和供应商手续费代码均不修改。

开发资料齐全后的落地顺序固定为：支付通道适配器 → 沙箱回调与主动查询 → 充值状态映射 → App 收银台启动方式 → 异常恢复与对账 → 小额真实充值验收。每一步通过后再开放下一步，正式配置不进入仓库。

## 必须等待快钱提供

- 正式接口版本、沙箱账号、商户号和证书。
- 精确签名、验签、字符集、回调应答、查询、关闭和退款规范。
- App/H5 收银台、回跳地址、错误码、限额、超时和重试规则。
- 对账文件格式、生产域名、IP 白名单和证书轮换规则。
- “充值卡时＋供应商兑付”业务模式的书面准入，以及企业付款能力说明。

资料未齐前，真实充值和供应收益兑付动作必须关闭；不得猜测字段、连接生产或展示“快钱已接通”。
