# 商店发布检查清单

## 已完成

- 独立 Expo 57 / React Native 工程
- Android 与 iOS 唯一包标识
- Android `versionCode` 与 iOS `buildNumber`
- 自适应图标与 URL Scheme
- 无敏感设备权限
- 应用内隐私用途说明
- Android APK / AAB 构建脚本
- Release 构建缺少正式签名时自动失败
- Release 构建缺少真实 Expo 项目 UUID 时自动失败；预检从 AAB 内部复核实际嵌入值
- 正式构建要求 EAS 在线查询结果与显式 Expo UUID 一致，不能只凭 UUID 格式通过
- 构建和预检均要求商店最高版本码或“从未上传”声明二选一，缺省和冲突输入都会失败
- CloudPay 专用 Google Play 上传证书（私钥保存在源码目录外）
- AAB 结构、清单、权限、签名和正式域名自动预检
- Android 包内源码指纹与当前唯一主前端自动比对；任何历史 APK/AAB 都不能冒充当前候选物
- Android 发布工具可自动发现本机有效的 OpenJDK 与 Android SDK；终端未设置环境变量时不再产生伪失败，真实门禁条件不降级
- ARM64 独立 APK 冷启动验证
- Android 提供方全链路验收：新建资源、三类材料上传与安全检查、资源验真、卡时核价、资源/价格双审、发布可售容量
- Android 上架下一步直达验收：首次新增直达原资源表单；保存成功和待补材料均按服务端资源 ID 直达对应三项材料清单；重复资产不会创建第二份资源
- Android 创建方案直达验收：资源验真通过后按资源 ID 直接打开四步向导；默认服务名称先保存到服务端，冷启动恢复不丢失且不会重复建草稿
- Android 提供方中断恢复验收：上架草稿自动保存，App 退出后可从提供工作台继续
- Android 半成品凭证恢复验收：只填写核价凭证来源便退出，重新进入仍保留输入；正式送审校验不放宽
- Android 提供方断网保护验收：保留上次草稿与挂牌状态，继续填写和挂牌管理自动锁定；恢复同步后才重新开放写操作
- Android 不确定提交结果恢复验收：材料上传/送审、方案送审与挂牌发布使用同一幂等请求安全重放，并以服务端权威状态回读确认；无法确认时保留原内容，不显示伪成功
- Android 方案自动保存恢复验收：普通草稿与审核补件草稿在回包丢失后回读服务端版本和完整内容，匹配才确认保存；未确认内容可原地重试，真实并发修改不被覆盖
- Android 旧签名冲突保护：预览入口只允许在模拟器自动替换同包名旧签名安装，物理设备拒绝自动卸载，防止误清用户数据
- Android 本地登录验收：仅本地验收构建按同一手机号自动带入测试后端生成的验证码；正式构建不开启该能力
- Android 入驻提交恢复验收：回包丢失后按公司名称、联系人、脱敏信用代码和审核状态回读确认；不匹配时保留表单，不显示伪成功
- Android 上架草稿放弃验收：二次确认、版本并发保护、前端/缓存/后端同步移除，已验真资源保持不变
- Android 上架草稿放弃回包恢复验收：只在服务端权威草稿列表确认原草稿已不存在后移除页面与加密缓存；无法确认时继续保留
- Android 过期方案重审恢复验收：同一请求可安全重放，且只在同一方案进入审核中、方案版本和提交版本各精确增加一版后确认成功
- Android 挂牌状态与服务端一致性验收：新挂牌、暂停、恢复均由服务端状态驱动
- Android 挂牌管理回包恢复验收：暂停、恢复、结束销售只在回读到同一挂牌的目标状态后确认，并同步页面与加密缓存，防止弱网回退
- Android 买卖视角闭环验收：同一账号完成双审与挂牌后，一键切回购买视角即可在市场看到同一资源和审核锁价
- Android 审核退回恢复验收：审核意见从消息直达原步骤，字段保留，修改后生成新一版双审且旧审计不被覆盖
- Android 工作台状态同步验收：进入页面、回到前台和审核中轮询均能获取最新结果，双审通过后立即开放挂牌
- Android 卡时价格展示验收：六位结算精度保持不变，挂牌、市场、管理和购买界面统一显示两位单价并展示人民币核价依据
- Android 重新交付闭环验收：买方原因、提供方二次交付、原订单状态和预留卡时同步，过程不重复扣款或生成第二个订单
- Android 全额退款闭环验收：退款确认金额、买方余额、预留卡时、可售容量和提供方待结算同步；剩余金额不会显示为负数
- Android 提供方待办验收：争议订单计入“需要处理”并优先展示，不依赖订单列表是否内嵌操作数组
- Android 提供方接单恢复验收：确认接单和开始交付使用稳定请求标识安全重放，并以同一订单的服务端时间与状态链确认结果，其他状态变化不得冒充成功
- Android 验收后售后验收：买方部分补偿申请暂停结算，提供方待办可见，提供方异议进入平台队列，平台裁决金额不可篡改
- Android 售后账务验收：部分补偿精确退回买方并只扣减提供方待结算；已验收订单不恢复已消耗容量
- 正式 AAB bundletool 结构验证
- Expo Doctor 20/20 项兼容性检查通过
- 应用内账户删除路径
- 可脱离 App 使用的公开账户删除页面及接口
- CloudPay HTTPS API 接入
- 国内直装 APK 与 Google Play AAB 使用独立构建通道
- Play AAB 不包含支付宝/微信 SDK、充值入口、外部购买引导或新增订单动作
- Play AAB 仍完整保留提供方资源录入、双审、补件、上架、履约和结算
- Play AAB 会从包内复核提供方能力开关及资源、草稿、挂牌、接单、交付和退款接口标记；本地隔离测试 AAB 已通过
- 商店通道写接口由服务端再次拒绝，避免旧客户端误触充值或新增订单
- 生产后端部署包已生成并通过 55 个测试文件、244 项测试；当前移动端接口契约校验覆盖 104 个调用、93 条路由
- 算力订单采用即时自动履约：付款先预留卡时，平台确认有空闲 GPU 槽位后才创建订单；实例与连接验真成功后才开始计费，5 分钟内无法完成交付则全额退回并释放槽位
- 首次获取 SSH 前会同步复核容器、GPU 分配和授权密钥；尚未使用即失效的订单原子全退并释放槽位，已进入使用中的订单只按签名计量回执结算
- 下单接口成功后 App 立即打开服务端返回的订单，再在后台刷新全局数据；刷新断网不会把成功订单误报为失败或诱发第二笔冻结
- 上架资源统一为“1 张 GPU × 使用小时”的独享 GPU时商品；8 卡节点最多同时承接 8 笔单卡订单，第 9 笔在预留卡时前拒绝
- 生产后端部署包已通过隔离目录 `npm ci --omit=dev` 与编译入口独立加载门禁
- systemd 与容器入口均会在配置不完整时拒绝启动，不会把半可用服务加入生产流量
- 目标机单命令验收已从最新压缩包独立执行并通过 8 项：文件摘要、密钥排除、38 份迁移、Node、生产依赖、编译入口及两种失败关闭
- 部署与路由契约 15 项通过；H100 sidecar 的类型、私网 HTTPS 地址和单 GPU 约束进公开配置，令牌只进 Secret，API/迁移/备份共享配置且镜像摘要一致；ALB/Kubernetes/验证探针的接管路径相互一致，失败回滚只撤移动路径
- 已保存 `cloudpay.kai.com` 首页和既有 `/api/health` 响应基线；移动 API 路由接入后必须逐字节摘要比对，防止影响旧网站

## 正式提交前必须由运营主体补齐

- 将 `~/.cloudpay-release` 中的上传密钥与口令分别加密备份，并限制发布人员权限
- Apple Developer / Google Play / 国内应用商店账号
- 运营主体法定名称和统一社会信用代码
- ICP 与 APP 备案信息
- 用户支持邮箱、电话和法定主体信息
- 将新后端部署至 `cloudpay.kai.com`，使健康、就绪、隐私、条款和账户删除页面通过预检
- 真实短信、支付及支付回调服务
- 如需 Expo 推送：登录 Expo/EAS、绑定 `com.kaicloud.marketplace` 对应项目，将真实 UUID 作为 `CLOUDPAY_EAS_PROJECT_ID` 注入发布构建，并配置正式推送凭据；华为 APK 构建本身不依赖 EAS
- 各商店截图、描述、分级和数据安全表
- 从各 Android 商店与测试轨道确认 `com.kaicloud.marketplace` 已使用的最高 `versionCode`，通过 `CLOUDPAY_PUBLISHED_ANDROID_VERSION_CODE` 注入预检；若已用过 1，则先递增主包版本码再构建
- 若未来在 Play 版开放卡时充值或新增购买，必须先完成 Play Billing 接入、服务端 token 验证和目标市场政策复核

服务端 `/mobile/v1/readiness` 与 `npm run release:preflight` 必须同时通过。不得凭人工判断绕过失败项。
