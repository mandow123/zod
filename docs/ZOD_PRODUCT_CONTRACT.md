# Zod App 产品合同

本文件记录已批准且必须长期保持的移动端产品规则。界面、接口、测试和运营配置都不得绕过这些规则。

## 信息架构

- 底部导航固定为：首页、市场、我的资产、消息、我的。
- “我的资产”对所有用户可见，并作为一级入口。
- KAI 卡时是二级账户页，可从首页、我的资产和我的进入，不占底部导航。
- 购买方与提供方共用一个账号和交易主体。全局视角切换只放在“我的”，其他页面不得重复展示切换器。
- “我的资产”内部可按“我购买的 / 我提供的”筛选；状态归并为待处理、托管与部署、运营中、生命周期。
- 上架入口在“我的资产”右上角以及提供方工作区中出现，权限不足时隐藏写操作但保留已发生事实。

## 卡时闭环

- 市场、商品、确认下单、订单、履约、退款和我的资产只使用 KAI 卡时。
- 上述交易链路不得显示人民币价格、人民币参考价或人民币与卡时的并列换算。
- `1 KAI 卡时 = 1.002 元` 只允许出现在充值、供应商兑付以及法务/财务规则中。
- 用户充值后公司确认收款并发放卡时；购买时预留或扣除卡时；履约完成后按服务费规则将净卡时结算给提供方；提供方可申请兑付。
- 所有卡时界面统一显示两位小数，账本仍使用整数微卡时计算。

## Spark 活动合同

- 商品通过 `campaignKey=nvidia-dgx-spark-200-baige-20off` 与 `productType=physical_delivery` 识别，禁止依赖标题、固定商品 ID 或库存数量识别。
- 供应商显示为“白鸽在线”，范围只限该 Spark 活动。
- 库存为 200 台；原价 `40,668.66 KAI 卡时/台`；优惠标签为 `8 折`；成交价 `32,534.93 KAI 卡时/台`。
- 服务端保存原价、8,000 折扣基点、成交价和活动版本；创建订单时锁定这些快照。前端只展示服务端值，不自行换算或二次打折。
- Spark 是实物设备采购，必须收集收货地址并进入设备订单、物流、收货及七天自动结算流程，不能伪装成按小时算力资源。

## 权限与资产

- 服务端返回当前交易主体、订单 `side`、允许的 `actions` 和功能可用性；客户端不得从全局视角或文案猜测权限。
- 主体切换时立即清除旧主体的余额、订单、资产、兑付和工作区快照，再加载新主体数据。
- 设备物流单号在服务端加密保存，不写入日志；列表只返回脱敏摘要，买方在已认证详情中才能查看用于追踪的信息。
- 设备订单由系统在收货七天后自动结算；普通供应商界面不得出现手动结算按钮。
- 手续费策略需运营双人审批后生效。迁移不得自动激活费率，也不得创建虚假管理员或虚假交易主体。

## 发布闸门

- 交易能力按具体动作判定，不以“服务在线”替代支付、下单、上架、兑付或通知能力。
- 任一权威字段、权限或服务能力缺失时，客户端必须安全关闭对应写操作并给出明确原因。
- 正式构建不得包含未标注的演示资源、虚拟成交或虚拟收益。
- 上架前必须通过类型检查、单元测试、前后端契约检查、Android 构建和关键购买/履约路径验收。

## 产品经理代码审计

- 每一次 Git commit 都必须先由唯一 App 产品经理审计本次暂存代码。
- 审计必须核对本合同的产品结构、交易红线、视觉规则、前后端一致性和上线风险。
- 审计结论必须明确为 `APPROVED`；任何有条件通过、待整改或不通过都禁止提交。
- 审计记录必须绑定当前基线提交和暂存差异摘要，并随同该次 commit 保存到 `docs/product-audits/`。
- 仓库提交门禁会校验审计记录；摘要不匹配、基线不匹配或没有批准记录时拒绝 commit。
